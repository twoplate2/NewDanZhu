# 1% Low 优化方案（v2）

更新：2026-09-20。**v1 已死**（降帧率换 1%low），死因见「已否定的方向」第 1 条。

> 本文只记录**真实呈现长帧**的优化路线。不比纯物理吞吐、不降分辨率、不关 MSAA、
> 不删动画、不隐藏正常 UI —— 与老版交接文档 `android/jiaojie.md:123-129` 同一口径。

---

## 〇、一句话现状

**我们的 Python 不是问题**（慢帧里 `_frame` 自算 0.01~0.58ms，165Hz 预算 6.06ms）。
**真问题是每一根慢帧都落在「1.35~1.45 个刷新周期」上** —— 即「**刚好错过一格 vsync，多等一整格**」。
把它压回 1.0，1%Low 就等于平均帧率。**这一仗跟帧率档无关，花平均帧买不到。**

## 一之二、⚠️⚠️ 「165Hz 面板自动降到 118」—— 做出来了，然后**撤掉**（2026-09-20 玩家拍板）

**它确实有效**（事实 #46）：165Hz 面板上把 Kivy 帧率上限从 165 降到 118，
`1%Low` 从 **112** 抬到 **122**（+9%），卡顿帧从 3 变 0，代价是平均帧 −4%。
代码一度写进了 `config.FPS_CAP_ON_165HZ_PANEL` 与 `device._apply_fps_cap()`。

**撤掉的三条理由**（核查整条链之后才看清，当时只看见"+9%"）：

1. ⚠️⚠️ **它帮不到最需要它的人。** 判据是「玩家从没手动选过档」
   （`_fps_user_cap() == FPS_CAP_DEFAULT`）。而 **0.8.81 之前的默认档就是 120** ⇒
   老存档里存着 `fps_cap_setting = 120` 的玩家判据**不成立** ⇒ **特判不生效**，
   他会一直停在 120。**最需要被抬起来的那批人恰好拿不到。**
2. ⚠️ **判据本身分不清两种情况**：「玩家明确把滑条拖到顶格」与「从没选过」在存档里
   长得**一模一样**（初值就是 `FPS_CAP_DEFAULT`），而注释里写的是"玩家一旦自己选过**任何**档就让位"。
3. ⚠️ **一个"只对某个面板、只对某种存档状态生效"的例外，维护成本大于收益。**
   撤的时候已经发现：两处注释 + 一处 changelog 还在论证旧的 **120**（代码取 118、注释论证 120），
   两条测试基线（`ast_parity` / `sig_parity`）写进去之后**忘了重采，一直是红的**。

**⇒ 要试这条路的玩家自己在设置里选 `120` 档**（`FPS_CAP_OPTIONS` 里有），不需要产品替他决定。
**⇒ 撤掉的代价写在明处**：165Hz 上 `1%Low` 回到 **112.1 / 111.7**，每轮约 **3 帧**
（5283 帧里）跌破"中位帧率 55%"那条线。**⇒ 完整实测账留在 `changelog/2026-09-20.md`。**
**⇒ ⚠️ 别再以"实测 +9%"为理由把它捡回来** —— 那条数据是真的，被否掉的是产品规则本身。

**同时定稿的档位表**：`FPS_CAP_OPTIONS = (60, 90, 120, 144, 165, 240)`
（顶格从 185 改成 **240** —— 它是"跟随面板/不设限"那一格，将来出 240Hz 面板直接能用）。

## 三、生态调研结论（2026-09-20）

- **Kivy / python-for-android 生态里没有任何一条讨论 120/165Hz 高刷，也没有任何一条讨论 1% low。** 只有零星的「帧率掉了」issue（kivy #6781 / p4a #2002 / kivy #8997）。
- **社区的通用清单我们基本吃透了**：widget 创建慢→已预烘；Cython→逻辑只占 0.1ms；atlas→字体子集化；`autoclass` 慢→已缓存类对象；阻塞活→发声/震动/落盘/守卫都搬了；`StencilView` 拖慢→**全工程零 `StencilView`**。
- **问题本身有官方解**：[Android Frame Pacing Library（Swappy）](https://developer.android.com/games/sdk/frame-pacing)。它的 `SWAPPY_SWAP_60FPS/30FPS` 就是「花平均帧」的官方形式，auto mode 会按前几帧平均时长自动降档。**但它要替换 `eglSwapBuffers`，在 SDL2 native 里 —— Python 侧够不到。**
- ⚠️ **Swappy 明确否掉了我们现在的做法**：「以渲染 API 允许的最快速度提交帧」→ buffer stuffing、多一帧延迟、**恶化帧率不一致**。
- ⚠️ **SDL 自己承认没解决**：vsync 状态启动时静默翻转（[#14642](https://github.com/libsdl-org/SDL/issues/14642)）、AChoreographer 支持还在提议（[#15013](https://github.com/libsdl-org/SDL/issues/15013)）、帧同步子系统还在 wishlist（[#10160](https://github.com/libsdl-org/SDL/issues/10160)）。
- ⚠️ **一条悬在我们全部结论上方的刀**：SDL 论坛「Uneven V-sync」帖指出「**有些 GPU 驱动不在 present 里阻塞，调用提前返回、绘制是异步的 ⇒ 围绕它量的时间不是真实帧时间**」。我们的 `_FRAME_SWAP` 正是这么量的。

### ⭐⭐ 不用重出 APK 就能跑新代码（`tools/emu/push_code.sh`）

**为什么能**（逐条实测过）：

| # | 事实 | 怎么验的 |
|---|---|---|
| ① | APK 是 **debuggable**（CI 跑 `buildozer android debug`）⇒ **`run-as` 能进应用私有目录** | `adb shell run-as org.danzhu.tiao id` → `uid=10052(u0_a52)` |
| ② | p4a 把 Python 代码解压在 `/data/data/<pkg>/files/app/`（**`.pyc`，legacy 布局**） | `danzhu/config.pyc` / `main.pyc` / `p4a/hook.pyc` |
| ③ | **只在首次启动解压**，之后不覆盖 | push 一个标记文件 → 重启两次 → **它还在** |
| ④ | `.pyc` 的 magic **一致**（本机 Python 3.11 = APK 里的） | 两边都是 `a70d0d0a` |
| ⑤ | 模块树**一致** | 设备 30 个 `.pyc` ↔ 本工程 30 个 `.py`，**差集为空** |

**⇒ 本地 `compileall -b` → 打包 → `run-as` 覆盖 → 重启 = 模拟器上跑当前工作区代码。**

⚠️ **三条边界**：
1. **日志头里的 `v0.8.xx` 不代表推的代码版本**（它读 `buildozer.spec`，那个不在 `app/` 里）
   ⇒ **验证代码版本只能看行为，不能看版本号。**
2. 不换资源（`assets/` `fonts/` `voice/`）与 `_python_bundle`（Python 本体）。
3. **只对 debug APK 有效**（release 包 `run-as` 会被拒）；出货仍走 CI。

**回滚**：`bash tools/emu/push_code.sh --restore`（回滚 `danzhu/`；`main.pyc`/`p4a/` 当时没单独备份，
要回滚它们得 `adb install -r` 重装）。

### ❌ 不能用它做的（**硬墙**）

0. ⚠️⚠️ **模拟器的「离群帧」是它自己的 artifact，`1%Low` 的绝对值被它污染。**
   两次抓到的百毫秒级离群**都是「纯 swap 阻塞」**：

   | 轮 | 帧间隔 | `等屏幕` | `自算` | 主线程 |
   |---|---|---|---|---|
   | 60Hz 第一轮 | 438.31 | **435.65** | 0.74 | 2.20 |
   | 120Hz 多轮 r1 | 196.08 | **194.69** | 0.41 | 1.58 |

   **⇒ `等屏幕` 吃掉全部，我们自己的代码认领 <1ms；落在不同阶段（装杯 / 飞行）。**
   真机慢帧是 20~40ms 量级，**没有这种东西**。
   **⇒ 模拟器上的 1%Low 只能用于「同设置内的相对比较」与「形状判断」，不能当绝对值。**
1. **刷到 120Hz 也只有 120Hz**（真机是 165Hz / 6.06ms 预算，这里是 8.33ms）⇒
   **165Hz 那套量化行为仍然测不了**，`vsync=-1` / 帧率档位的效果也测不了
2. **ARM→x86 转译 + 虚拟 GPU** ⇒ **绝对数值一概不可外推**
3. **`dumpsys gfxinfo` / `SurfaceFlinger --latency` 都拿不到游戏帧**（事实 #17）⇒ 外部校准这条路在这里断了
4. **⇒ 它替代不了真机**。老版 `jiaojie.md:129`「不以桌面微基准直接宣称 Android 1% Low 已改善」这条规矩，对模拟器同样适用

### ⚠️ 一个卡点：拿不到最新 APK

CI（`.github/workflows/build-apk.yml`）产出的是 Actions **artifact**（名字 `tiao-apk`），
而 **artifact 下载要认证** —— 公开仓库也一样：`HTTP 401 {"message": "Requires authentication"}`。
本机 `gh` 未登录，本地最新的只有 **0.8.74**。

**⇒ 想用模拟器测新代码，得先解决「APK 怎么拿到」**：让 `gh auth login` 一次、或把 CI 改成**发 Release**（Release 资产是免认证可下的）、或本地 WSL 构建。
